# Threat model (STRIDE-oriented)

| Threat                                   | Affected component        | Mitigation                                                                                                                 | Residual risk                                                                           | Validation                                                |
| ---------------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Stolen authorization code                | SPA OAuth callback        | PKCE code verifier bound to the browser session; short code lifetime; redirect URI allow-listed in Entra                   | Low; requires code + verifier interception                                              | Manual Entra config review; MSAL default PKCE behavior    |
| Token replay                             | API bearer validation     | Issuer/audience/signature/lifetime validated per request via `jose` + JWKS; tokens never logged                            | Token could still be replayed within its lifetime if exfiltrated                        | Unit tests for `validateBearerToken`; log redaction tests |
| CSRF                                     | API state-changing routes | Bearer-token auth (no ambient cookie credential) removes classic CSRF vector for API calls                                 | None material                                                                           | Architecture review                                       |
| XSS                                      | SPA                       | CSP (`script-src 'self'`), React's default output encoding, no `dangerouslySetInnerHTML` usage                             | Third-party dependency compromise                                                       | CodeQL, dependency review, CSP                            |
| Malicious organization parameter         | Azure DevOps adapter      | Strict allow-list regex before any URL construction (`assertValidOrganization`)                                            | None material within pattern                                                            | Unit tests: `estimate-client.test.ts`                     |
| SSRF                                     | Azure DevOps adapter      | Host is always a trusted constant; only the validated org path segment varies                                              | None material                                                                           | Unit tests asserting host cannot change                   |
| Cross-tenant data exposure               | Report store              | Every read/export/delete checks `(subject, tenantId)` ownership                                                            | Low; relies on correct claim extraction                                                 | Integration test: cross-tenant report access rejection    |
| Insecure direct object reference         | Report IDs                | Opaque random IDs (`newOpaqueId`), not sequential, plus ownership check                                                    | Low                                                                                     | Unit test for ID randomness; ownership tests              |
| Leaked report download                   | Export endpoints          | Bearer-auth required, `Cache-Control: no-store`, ownership-checked                                                         | Link sharing by the customer themselves is out of scope                                 | Manual review                                             |
| Spreadsheet formula injection            | CSV/XLSX export           | Values starting with `=+-@` are neutralized (`sanitizeCellValue`/`sanitizeCsvField`)                                       | None material                                                                           | Unit tests: `sanitize.test.ts`                            |
| Log leakage                              | Logger                    | Pino redact paths cover tokens, secrets, email/UPN; identity values masked                                                 | Misuse of `logger.info` with unredacted fields by future contributors                   | Code review checklist; redaction unit test                |
| Overbroad consent                        | Entra app registration    | Only `vso.advsec`-equivalent delegated scope requested; no automatic scope broadening on failure                           | Tenant admin could grant broader consent manually                                       | `docs/ENTRA_SETUP.md` guidance                            |
| Consent phishing                         | Consent explanation page  | Clear, plain-language consent page before redirect to Microsoft; redirect always goes to `login.microsoftonline.com`       | User could still be phished outside the app                                             | UX copy review                                            |
| Compromised dependency                   | npm packages              | Dependency review + CodeQL + secret scanning in CI; pinned stable versions                                                 | Zero-day in a dependency                                                                | CI gates (`dependency review`, `codeql`)                  |
| Denial of service                        | API                       | Function App scaling limits (`maximumInstanceCount`), request body/query size limits                                       | Distributed volumetric attack (out of scope for app-layer controls)                     | Load testing (follow-up)                                  |
| Rate-limit exhaustion                    | Azure DevOps adapter      | Bounded retries with jitter; `Retry-After` respected; no unbounded retry loops                                             | Azure DevOps org-wide throttling by other callers                                       | Integration test: 429 with Retry-After                    |
| Malicious repository or identity strings | Export/rendering          | Formula-injection sanitization; React output encoding for display                                                          | None material                                                                           | Unit tests                                                |
| Stale retained reports                   | Report store              | TTL-based expiry per retention tier (`RETENTION_TTL_MS`); explicit delete endpoint                                         | Session/thirty-day durable store not yet implemented (in-memory only in this iteration) | See `docs/BUILD_REPORT.md`                                |
| Incorrect identity deduplication         | Identity matching         | Conservative matching: only exact email/UPN or approved alias auto-merge; noreply/login-only candidates flagged for review | False negatives (missed matches) are preferred over false positives                     | Unit tests: `identity-matching.test.ts`                   |
